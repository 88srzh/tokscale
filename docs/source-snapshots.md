# Source snapshot export

This contract applies only to `tokscale graph --source-snapshots --no-spinner`. The following TypeScript types describe the additive JSON fields; `DailyContribution` is the existing graph daily JSON type, including `date`, `totals`, `intensity`, `tokenBreakdown`, and `clients`.

```ts
type SourceUsage = {
  version: 1;
  eventIdentityVersion: 1;
  capturedAt: string;
  fullHistory: boolean;
  replacementClients: string[];
  partialClients: string[];
  bucketTimezone: string;
  dayKey: string;
  rowsWithoutIdentity: Record<string, number>;
  sessions: {
    client: string;
    sessionId: string;
    days: DailyContribution[];
    events: { id: string | null; days: DailyContribution[] }[];
  }[];
};
```

`graph --source-snapshots` adds `sourceUsage` with `version: 1`, `eventIdentityVersion: 1`, a pre-parse ISO `capturedAt`, `bucketTimezone`, and `dayKey` in that zone. Each `(client, sessionId)` contains all emitted usage in the requested window as `days` using the normal graph daily JSON shape. IDs and client scope are observed before date filtering, so an observed session outside the window has `days: []` and `events: []`. `fullHistory` is true only without `since`, `until`, or `year` bounds. It grants replacement authority only for the literal non-synthetic selections in `replacementClients`; explicitly selected Token Monitor-owned clients (`token_monitor::client_ids()`) have complete coverage without joining default scans, and the explicit `9router` filter has complete coverage of its own emitted partition and is included, while `gjc` also covers `9router`. `partialClients` lists observed raw clients without complete selection coverage, including clients admitted only through `synthetic`. A synthetic-only scan of OpenCode gateway traffic does not authorize replacing its complete session. Default selection includes the real clients plus synthetic traffic; the real selections retain authority. Consumers first reject raw session clients listed in `partialClients`, then normalize scanner aliases to their app parent (`cc-mirror/*` to Claude, `9router` through the GJC parent, and Antigravity surfaces through their app parent) before testing replacement scope, while retaining the raw `(client, sessionId)` storage partition. Normalizing a selected family surface must not promote another raw partial surface to authoritative. Windowed or partial snapshots cannot establish full-history replacement authority.

Each session also contains `events: [{ id, days }]`. A non-null `id` is `sha256:` followed by 64 lowercase hex digits: SHA-256 of UTF-8 `tokscale-source-event-v1` followed by a NUL byte, an unsigned 64-bit big-endian byte length of the family, the UTF-8 family, and the original UTF-8 parser `dedup_key`. The family is the emitted client except that `antigravity`, `antigravity-cli`, and `antigravity-extension` share `antigravity`, `cc-mirror/*` shares `claude`, and case-insensitive `9router` shares `gjc`, matching the scanner's dedup lanes. The export does not additionally hash the current session, path, day, model, tokens, or price, so ownership or accounting corrections preserve the digest when the existing dedup key stays the same. Independent client families cannot collide merely by reusing a key. Each event's `days` uses the same priced daily fold and JSON shape as session `days`; summing event accounting by date/client/model reproduces the session accounting using the existing saturated token/message arithmetic and normal floating-point rounding; provider labels are merged as a sorted set, as in the existing daily fold. Intensity is local to each group's days and must be recomputed after union; active time is not per-event accounting. All rows without a nonblank dedup key are combined into one `id: null` group per session. This group contributes to accounting but is unresolved, never an exact dedup identity.

For a full-history session in replacement scope, replace its entire snapshot, including event groups; do not merge per-day maxima. Across omitted retained session IDs, subtract only whole non-null event groups whose digests the current authoritative snapshots claim, then retain the unclaimed groups. This handles a previous dedup winner disappearing while another file/client/session becomes owner, including partially overlapping retained sessions. Compare identities across normalized family ownership, not just within the current session ID, and replace each claimed group's complete days/models/cost rather than keeping old maxima. An omitted session still does not prove deletion. Old snapshots lacking `events` or the supported `eventIdentityVersion`, and null event groups, cannot be reconciled exactly; report them as unresolved rather than fabricate identities, delete them wholesale, or call an additive union exact. Digest exactness is relative to the scanner's existing dedup keys: keys that embed session IDs, positions, timestamps, token data, or fallback metadata retain those stability limits. Different-key suppression such as Copilot session/timestamp precedence or OpenClaw mirror-turn coverage does not gain a shared identity from this export.

This is a scanner-authoritative snapshot of emitted parser rows, including Claude's `RetainObserved` cache while its transcript still exists, not a fresh-disk-only inventory. Clearing that cache can expose a smaller corrected snapshot; this mode intentionally accepts that correction and makes no change to cache accounting or native parser interpretation. Scanning is not atomic across files or concurrent writes. Torn/malformed input, unreadable sources, or parser warnings can produce incomplete rows without failing the export; `fullHistory` denotes the requested date scope, not successful complete parsing. Consumers must not treat a successful export or its capture time as proof that every source was read coherently.

`rowsWithoutIdentity` counts parsed rows per client before date filtering whose session IDs are empty, whitespace, the legacy `unknown` sentinel, or Copilot's `unknown-session`; their usage remains in aggregate contributions and outside identified session replacement. Copilot trace-ID fallbacks remain the parser's IDs; the export has no provenance bit to distinguish these from real session attributes and does not assert they are native session identities. Zero-token rows and empty model identities are retained when emitted by the parser. Recovered aggregates are excluded from both graph and snapshots to avoid recursive archiving. Submission and recovery payloads never include `sourceUsage`. If an unpinned local zone cannot be resolved to an equivalent IANA zone, this opt-in export asks you to configure a named timezone. Days are sorted by date; sessions by raw client and session ID; event groups by null first, then digest. Model contribution array order is unspecified. Event export is opt-in and retains BTreeMap contribution groups, not whole message vectors: extra memory/output grows with distinct session/event/day/model tuples and is therefore larger than a daily-only graph; digesting is linear in key bytes and event insertion is logarithmic in groups per session. It adds no dependencies or cache-format changes.
